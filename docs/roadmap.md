# 后续路线与未实现范围

本次目标是完整的本地框架，不是实机微信机器人或情感效果认证。下面是后续建设顺序，不代表已经实现，也不自动授权执行。

## 1. 模型质量与费用评估

- 在用户单独批准付费调用后，用匿名合成对话验证真实 Provider、结构化输出、fallback 权限与计费。
- 建立普通问候、误会、长期不满、无法兑现的要求、事实缺失、本人介入等质量集。
- 分别看表达自然度、事实/推测归属、虚构承诺、接管准确性、延迟、调用次数及费用。
- 根据评估决定路由、提示词和模型分配，不以更多 Agent 代替测量。

## 2. 个人微信实践

- 单独讨论设备、客户端版本、可接受接入方式、账号边界和测试授权。
- 在独立测试账号/合成会话核实读取、身份、自身回声、发送、重连、回执、未知投递和平台限制。
- 不预先承诺任何个人微信 Hook、桌面自动化或非官方协议能稳定使用，也不把企业微信能力套到个人微信。
- Connector 必须提供真实能力声明；没有能力时明确失败，不能悄悄回退 Mock。

**本次没有选择、安装或验证微信 Connector 实现。**

## 3. 其他消息平台

按统一事件和 SendIntent 协议增加适配；每个平台独立绑定账号/会话身份，测试幂等与投递查询限制。跨平台联系人关联必须显式建立，不能仅凭同名自动合并记忆。

## 4. 隐私与产品控制

真实数据接入前增加可执行的保留期、按会话导出/删除、备份生命周期、敏感信息策略与审计查看。明确消息对象对自动化及第三方处理的知情安排。若需要 UI，在管理 API 之上另建，本次没有 Web 管理界面。

## 5. 生产运行能力

PostgreSQL 已是唯一业务数据库，但仍需根据实际负载建设版本升级迁移、任务租约/分布式锁、监控、共享限流、权限分层、TLS 部署和漏洞审计 CI。当前不能多进程运行，不能通过简单添加 workers 扩容。

## 6. 更多消息能力

群聊、多媒体理解、主动联系、跨会话检索、图节点 checkpoint、复杂长期记忆均未实现。添加这些能力需要新契约、权限边界和行为验证，不能仅扩大模型提示词后声称可用。
