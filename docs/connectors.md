# Connector 协议与接入

## 当前实现

| 渠道 | 状态 | 说明 |
|---|---|---|
| `mock` | 可运行的本地模拟 | HTTP/CLI 注入事件，独立模拟收件记录，支持按发送 ID 查询 |
| `wechat` | 未实现 | 仅保留类型与明确错误，不读取、修改或操作微信 |

个人微信接入可使用后续选定的本地桥接、正式适用接口或授权客户端自动化；框架不预设一种路线已验证。不存在因微信不可用而自动改用 Mock 的降级行为。

## 输入事件

```json
{
  "channel": "mock",
  "account_id": "demo-account",
  "conversation_id": "demo-chat",
  "event_id": "external-123",
  "sender_id": "peer",
  "direction": "inbound",
  "origin": "peer",
  "message_type": "text",
  "conversation_type": "direct",
  "text": "今天有点累",
  "occurred_at": null,
  "client_send_id": null
}
```

`channel` 默认 `mock`，其他默认值见领域模型。`occurred_at` 如提供必须有时区；本机接收时间由存储层单独记录。标识符使用受限字符集，不能直接使用路径或任意控制字符。若未来平台标识不满足约束，由 Adapter 做稳定无碰撞映射，并自行保留对应关系。

- `inbound + peer`：对方的新消息。
- `outbound + bot`：带发送关联 ID 的机器人回声，只有与同会话发送记录匹配时才按回声处理。
- `outbound + human/unknown`：本人或无法可靠识别来源的发言，保守触发接管。
- 不支持的媒体或群聊：记录限制，不把空文本当作已经理解。

输入身份必须绑定实际 Connector 的注册账号；不能允许普通消息通过声明字段获得其他账号权限。Mock HTTP 入口只能注入 Mock 账号。

## 输出动作

Dispatch 调用 Connector 时提供：稳定 `send_id`、完整会话 key、正文及源修订号。Connector 不接受模型生成的任意鼠标指令、终端命令或收件人覆盖。

返回结果为：

- `sent`：渠道明确报告发送成功，含可选外部消息 ID。
- `failed`：渠道明确报告未成功。
- `unknown`：无法确认；禁止自动重发。

超时不等于失败。连接恢复后通过 `query(send_id)` 查询，或由管理者明确核对。回执缺失也不能一概推断未发送。

## 能力声明

Connector 报告自身是否可用、不可用原因、文本发送、投递查询和发送幂等能力。不能把模拟能力当成真实平台保证。

未来接入还必须明确：

- 是实时事件、轮询、数据库还是可见窗口读取。
- 读取是否触发已读、切换窗口或抢占焦点。
- 历史范围、媒体范围和群聊限制。
- 是否能区分机器人回声与本人手动发言。
- 发送成功具体代表操作执行、本机确认还是服务端确认。
- 客户端版本、断线恢复和账号限制。

## 接入真实微信时的工作顺序

1. 独立确认接入路线、版本支持、许可及账号风险。
2. 实现协议并使用测试账号验证，不在真实伴侣聊天上首次试运行。
3. 通过标准化事件、发送、未知结果与自身消息过滤的契约测试。
4. 明确声明仍缺失的能力，不将其包装为支持。
5. 配置精确账号/会话白名单，再显式开启自动模式。

以上步骤是后续路线，**当前仓库没有执行真实微信接入验证**。
