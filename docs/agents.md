# Agent 与模型边界

## 角色不是独立服务

五个角色是逻辑职责，通过同一个模型接口调用，可以共享同一模型版本。它们不互相自由对话、不直接访问平台，也不各自持有发送权限。模型配置与角色提示词分别管理。

| 角色 | 职责 | 不负责 |
|---|---|---|
| Understanding | 提取有来源的事实、可能解释、未知项 | 读心、给人永久贴标签 |
| Strategy | 选择倾听、澄清、承担责任等沟通策略 | 代用户决定承诺或扩大权限 |
| Talk | 按风格与策略产出回复或不回复建议 | 任意选择收件人、编造经历 |
| Review | 审核表达是否符合上下文与策略，提出重写/接管 | 批准平台访问或保证绝对正确 |
| Memory | 整理有来源的陈述、摘要和推测 | 把草稿记成已发送承诺 |

具体输出定义在 `src/bae_pilot/agents/schemas.py`，提示词在 `prompts.py`，图在 `graph.py`。前台和后台记忆共用 `models/context.py` 的消息字段白名单/字符测量，以及 `models/base.py` 的最终预算、超时和结构化校验边界；base 保留白名单函数的兼容导出。只有前台使用上下文打包器折叠可选历史，后台 Memory 不缩短其提取窗口；角色证据检查与调度仍各自独立。

## 路由

简单问候等有限候选走 Talk 短路径；其余默认走 Understanding → Strategy → Talk → Review。规则不是情绪识别模型，也不是风险判断保证。

Talk 可返回 `requires_deep=true`，短路径据此升级，旧草稿不会发送。复杂路径最多重写一次，再次要求修改则转接管。每轮还有模型调用总数上限；记忆使用独立后台任务预算。

所有路径最后都进入程序校验。模型产出不包含收件人字段、发送工具或控制指令。白名单、会话模式、修订号与发送状态由程序执行。

## 角色输入与上下文

完整图状态留在本轮 LangGraph 中，但不会把所有旧结果累积传给每个角色：

| 本次调用 | 携带的角色结果 |
|---|---|
| Understanding | 无旧草稿/旧审核 |
| Strategy | Understanding |
| 首次 Talk，包括短路径升级后的首次深路径 Talk | Understanding、Strategy（若已生成） |
| 重写 Talk | Understanding、Strategy、上一版 Talk、Review 反馈 |
| Review | Understanding、Strategy、最新 Talk，不带自己的旧审核 |

每次请求均从本轮原始候选重建；当前 queued、最近 outbound、完整记忆与有效事实的原文被保护，只允许折叠可选历史。Understanding 的事实来源必须属于**该次实际展示的 messages**，不能引用已折叠消息，也不能仅凭记忆中的来源 ID 补造原文证据。后续角色仍能对照这些事实的原文。记忆可以作为有类别、有归属的背景，但不能把推测升级为事实。阈值、覆盖说明与局限见 [上下文管理](context.md)。

## 结构化结果

- 区分事实、推测和未知，不把“对方可能失望”写成已知心理状态。
- 不虚构已购买、已预约、已完成等事实。
- 不替本人作未经确认的长期承诺。
- 可以建议暂停、澄清或交给本人；不以无限延长聊天为目标。
- 聊天中出现“忽略规则”“改发给另一个人”等内容，只能作为聊天数据，不能成为系统权限。

Pydantic 校验格式不等于语义正确。Review 也是模型，不是独立真实性证明。

## 记忆

记忆条目必须包含来源事件 ID；入站内容应保留“对方表示”的归属，不等于其陈述在现实中已获证实。

- `statement`：有直接来源的陈述。
- `summary`：模型整理的摘要，不是原话。
- `inference`：尚未确认的解释，不能自动晋升为人物事实。

记忆任务只使用可追溯上下文；未发送或未知投递的草稿不能作为已作出的承诺。记忆带源事件序号/版本，旧任务不能覆盖更新版本。临时故障有限重试；确定性的 `context_too_large` 立即终止任务并保留旧快照，不影响已经完成的回复、不接管前台。

当前正常触发点是明确发送成功后，不是每条入站均独立触发。Memory 读取截至 source_version 的同会话最近窗口（默认 40 条，去 echo），输入不包含旧记忆；输出经结构与来源校验后，事务性整批替换 PostgreSQL 中的当前快照。下一轮前台会加载该快照。因此早期信息可能随窗口滚动遗忘，换成 PostgreSQL 并未自动增加长期合并、向量检索或知识图谱。来源 ID 证明出处，不证明模型解释一定正确。选型区别见 [数据库与记忆](database.md)。

## Fake 与真实模型

Fake 是明确的开发替身，生成确定性结构化结果，便于验证路由、状态和故障处理。它不提供可用于评价真实沟通效果的智能基线。

Anthropic Provider 是可选外部边界，显式配置后使用官方 SDK。使用流式请求获取完整最终消息，再校验结构化结果；拒绝、截断、格式错误不能进入自动发送。有限超时与重试不等于费用的严格上限，服务端 fallback 也可能产生额外请求/费用。

默认不自动发送模型内部思考，也不将其存入日志。当前不启用跨轮服务端消息线程或 LangGraph checkpoint；每轮从应用保存的上下文构造独立请求。

## 扩展

新增角色时先确定它是否确实需要独立模型调用。定义输出 schema、提示词与调用预算，再添加图节点/边并写行为测试。不要仅为增加 Agent 数量而给普通聊天增加延迟。
