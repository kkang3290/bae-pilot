# 架构

## 目标与边界

BaePilot 是本地优先的情感类对话系统。正常流程是对**明确授权的会话自动回复**，而不是每条生成草稿等人审批。提供完整的合成开发闭环：Mock 渠道 + Fake 模型 + 实际 LangGraph + PostgreSQL + 自动发送调度；不访问真实模型/平台，但需要数据库连接。

首版不是已接入个人微信的成品，不具备生产级账号托管或多节点能力，也不承诺情感判断正确。真实平台的稳定性、登录、兼容性与平台规则留给后续 Connector 实践。

## 分层

```text
HTTP / CLI / 未来平台 Connector
             ↓
Ingestion：身份绑定、校验、去重、入库、更新修订号
             ↓
PostgreSQL jobs → Runtime Worker → 上下文快照
                                  ↓
                        编译后的 LangGraph
                                  ↓
                      结果和 Outbox 事务落库
                                  ↓
Dispatch：授权、模式、修订号、有效期、频率、未知投递检查
                                  ↓
                    Connector.send → 记录结果
                                  ↓
                     异步 Memory job → 记忆
```

模型没有发送工具，也不持有渠道登录凭据。收件身份来自系统绑定，模型只产出内容和结构化建议。Mock HTTP 入口不能声明自己是微信。

## 会话身份

所有读写使用完整三元组：`(channel, account_id, conversation_id)`。内部使用规范 JSON 编码的 key，而不是用分隔符拼接，避免标识碰撞。事件去重使用该三元组加 `event_id`；`received_at`、数据库 ID 等本机生成值不参与载荷指纹。

相同标识、相同业务载荷是重放；相同标识、不同载荷是冲突。冲突不覆盖原事件。不同账号可以有相同的会话编号与平台事件编号。

## 一次处理的边界

1. 收到事件后先持久化，HTTP 返回接收状态，不等同于发送完成。
2. 静默窗口内的连续消息合并处理，并受最大合并窗口限制。
3. Worker 对同一会话串行生成，不阻塞新事件入库。
4. 每次运行捕获 `revision`，候选消息为最近窗口、本轮全部 queued 与最近非 echo outbound 的并集；每个角色再构造有预算的独立视图。普通候选走短路径，复杂交流走专家路径，短路径可升级。
5. 图没有外部发送副作用。完成后再次验证修订号，完整核对并精确确认本轮 queued 集合，事务性保存运行结果与发送意图；不确认未展示的当前消息。
6. Dispatch 在真正调用 Connector 前再次检查权限和修订号。
7. 成功投递后异步整理带来源的记忆。

上下文先移除角色不需要的中间结果；超过 90% 字符预算才折叠最旧的可选历史，通常整理到 80%。当前 queued、最近 outbound 锚点、完整记忆、风格及必要角色结果/事实原文不能删。覆盖说明与正文一起计入硬限，原始事件不删改。必要输入仍超限则该任务立即失败，不原样重试；只有仍为当前 revision 的前台运行才能转接管。后台记忆超限不接管、不清空旧快照。详见 [上下文管理](context.md)。

## 状态

会话模式：

- `auto`：在白名单和全局控制允许时自动回复。
- `paused`：暂停，可显式恢复。
- `handoff`：本人或异常接管，需要显式恢复。
- `stopped`：停止，需要显式恢复。

配置中的白名单始终是发送前提；把数据库模式改成 `auto` 不能授权白名单外会话。

Outbox：

```text
pending → sending → sent
                  → failed
                  → unknown
pending → cancelled / superseded
```

`sent` 表示 Connector 明确报告的发送成功，不自动等于对方已读。Mock 的成功只代表模拟收件记录存在。

新消息、接管和控制变化推进修订号，使旧生成结果失效。恢复自动模式时不追发暂停期间的历史消息；等待下一条新消息。

## 发送与未知结果

- 发送认领先落库，再调用 Connector。
- 超时、返回未知结果、或进程在 `sending` 期间退出，保守进入 `unknown`。
- 未知投递阻塞该会话后续自动发送，直到 Connector 查询或管理者明确核对。
- 核对不会把未知结果自动重发；确认失败的旧回复也不会在上下文已变化后直接发出。
- 暂停返回后不认领新发送；已经开始的外部调用可能仍完成。系统提供在途数量，不承诺远程撤回。

本地幂等不能证明外部渠道 exactly-once。真实 Connector 的幂等、发送查询、本人操作检测等能力必须如实声明。

## 持久化与恢复

PostgreSQL 是唯一业务存储：事件、会话、控制、运行、任务、Outbox、记忆、审计及 Mock 回执均在同一专用 schema。使用 Psycopg 异步连接、短事务、JSONB、原生时间和递增 identity。单个应用通过专用连接持有 database/schema 级 session advisory lock；仍仅支持一个服务进程、一个 Uvicorn worker，不使用 transaction pooling。连接丢失不会自动重连继续发送。详见 [数据库与记忆](database.md)。

首版**没有启用 LangGraph checkpoint**。重启会恢复安全的待处理任务，必要时重新执行无发送副作用的生成阶段。业务结果和 Outbox 是恢复依据，不承诺逐节点、逐 token 续跑。遗留的发送中状态必须先转为未知结果。

## 非目标

首版不实现真实微信 Hook/UI 控制、群聊、多媒体理解、主动发起关系对话、跨平台自动身份合并、向量检索、分布式队列、云端多租户或完整隐私合规。相关扩展见 [roadmap.md](roadmap.md)。
